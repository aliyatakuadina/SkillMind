# SkillMind LMS — план проекта

План следующего этапа — [AI-функции, трёхъязычные материалы и геймификация](docs/AI-GAMIFICATION-PLAN.md). В нём зафиксированы актуальные решения и журнал реализации после MVP.

## Summary

Подготовить файл `outputs/SkillMind-LMS-project-plan.md` с полной спецификацией MVP: React + TypeScript + Vite, Supabase и Vercel. Первый релиз включает обучение, конструктор курсов, тесты, задания, сертификаты, модерацию и расширенную аналитику; AI подключается только после стабильного запуска MVP на отдельном этапе.

Интерфейс — русский, с i18n-структурой для будущих переводов. Доступ к опубликованным курсам свободный: студент зачисляется сам.

## Key Changes

- Уточнить роли: `student`, `teacher`, `admin`; предусмотреть отдельный маршрут и проверки доступа для каждой роли.
- Расширить жизненный цикл курса: `draft → pending_review → published` либо `changes_requested` / `archived`. Администратор публикует курс или возвращает его автору с комментарием.
- Добавить зачисления (`enrollments`), чтобы отделить факт доступа студента от его прогресса.
- Оставить структуру «курс → модуль → урок → элемент контента», но формализовать типы `lesson_items`: форматированный текст, видео-ссылка/файл, PDF, DOCX-предпросмотр, тест, домашнее задание.
- Для DOCX требовать предварительный PDF-вариант: в уроке отображается PDF во встроенном просмотрщике без скачивания; исходный DOCX при необходимости хранится отдельно.
- Выделить тесты в отдельные сущности: тест, вопросы, варианты ответов, сопоставления, настройки проходного балла и лимита попыток. Сохранять историю попыток, лучший балл и статус прохождения.
- Разрешить сдачу домашнего задания текстом и несколькими файлами; определить допустимые MIME-типы, число файлов и лимиты размера в конфигурации проекта.
- Рассчитывать прогресс по обязательным урокам и обязательным тестам. Сертификат выдаётся, когда все уроки завершены и все обязательные тесты пройдены.
- Добавить сущности сертификатов, модерационных комментариев, событий обучения и аналитических агрегатов. События нужны для времени обучения, динамики прохождения и аналитики по тестам/заданиям.
- Настроить Supabase Storage с приватными бакетами для учебных файлов, работ и сертификатов; файлы выдавать по авторизованным правилам или временным ссылкам.
- Реализовать RLS: студент видит только опубликованные курсы, свои записи и доступные материалы; преподаватель управляет только своими курсами и их студентами; администратор модерирует пользователей и курсы.
- Подготовить i18n-слой: все пользовательские строки берутся из русских словарей, без жёстко прошитого текста в компонентах.
- Спроектировать страницы из наброска и добавить необходимые: каталог с фильтрами, просмотр урока, список курсов преподавателя, очередь модерации, страница сертификата, страница «Мои курсы», профиль и экран «Нет доступа».
- Реализовать расширенную аналитику автора: зачислено/активно/завершило, средний прогресс, динамика, среднее время обучения, результаты тестов, статусы заданий, карточка студента и экспорт CSV.
- На этапе 11 подключить AI только через защищённые Supabase Edge Functions: транскрипция, субтитры, summary, генерация структуры и тестов, чат по материалу. Ключи API не попадают во frontend; добавить очередь задач, статусы, обработку ошибок и лимиты расходов.

## Development Stages

1. Зафиксировать пользовательские сценарии, MVP-границы, роли и критерии готовности.
2. Создать информационную архитектуру, карту маршрутов и прототип навигации.
3. Описать дизайн-систему, адаптивные макеты и i18n-структуру.
4. Собрать статический React-интерфейс с демонстрационными данными.
5. Спроектировать миграции Supabase, типы TypeScript и Storage-бакеты.
6. Подключить Supabase, авторизацию, профиль и ролевые guards.
7. Реализовать CRUD конструктора, упорядочивание модулей/уроков/контента и загрузку файлов.
8. Реализовать каталог, зачисление, прохождение уроков и расчёт прогресса.
9. Реализовать тесты, попытки, домашние задания, проверку и сертификаты.
10. Реализовать модерацию, административную панель и расширенную аналитику с CSV.
11. Подключить AI через Edge Functions после проверки стабильности MVP.
12. Провести интеграционные, RLS-, адаптивные и accessibility-проверки.
13. Настроить GitHub, переменные окружения и проверочный CI.
14. Развернуть frontend на Vercel и Supabase production-проект.
15. Добавить геймификацию и другие функции только после анализа использования MVP.

## Test Plan

- Регистрация, вход, выход, восстановление сессии и запрет доступа к чужим данным.
- Создание, редактирование, отправка на модерацию, возврат и публикация курса.
- Свободное зачисление, отображение материалов, просмотр PDF и видео, корректный PDF-предпросмотр DOCX.
- Расчёт прогресса, ограничения и результаты попыток теста, выдача сертификата только при выполнении условий.
- Загрузка нескольких файлов к заданию, проверка, оценка и обратная связь автора.
- Результаты аналитики, экспорт CSV и отсутствие доступа автора к данным чужих курсов.
- Проверка RLS напрямую через Supabase, мобильной адаптивности, клавиатурной навигации и сценариев ошибок.
- После AI-этапа: авторизация Edge Functions, обработка долгих задач, повтор запуска, лимиты и отсутствие ключей в браузере.

## Assumptions

- Оплата, подписки, чат между пользователями, live-занятия и геймификация не входят в MVP.
- Сертификат виртуальный: уникальный номер, данные студента и курса, дата выдачи, страница проверки; PDF-экспорт можно добавить отдельной задачей.
- Сложная оригинальная вёрстка DOCX сохраняется через обязательный PDF-предпросмотр.
- Автор задаёт проходной балл и лимит попыток для каждого теста.
- AI не является условием публикации MVP и не обрабатывает данные в браузере напрямую.
