# Контракты данных AI и геймификации

Это техническая основа [согласованного плана](AI-GAMIFICATION-PLAN.md), а не утверждение о готовности AI-функций. Пользовательские операции записи, worker, генерация и начисление наград добавляются следующими этапами. Переключатели функций пока выключены.

## Доступ

| Данные | Студент | Автор курса | Администратор | Сервер |
|---|---|---|---|---|
| Исходники `media_sources` | Нет | Свой курс | Да | Да |
| Загрузки S3, аренда задачи | Нет | Нет | Нет через клиент | Да |
| Статус AI-задачи | Своя задача доступного курса | Своя задача доступного курса | Да | Да |
| Вход/результат и этапы генерации | Нет | Свой авторский черновик | Авторские задачи, не чат | Да |
| Попытки провайдеров, каталог, конфигурация | Нет | Нет | Да | Да |
| Опубликованный RU/KK/EN-пакет | При доступе к курсу | Да | Да | Да |
| Черновик/история пакета | Нет | Свой курс | Да | Да |
| Диалог | Только свой, при доступе к курсу | Только свой | Только свой | Для выполнения запроса |
| Личный XP, цели, достижения, сырые очки | Только свои | Только свои | Только свои | Да |

На всех 23 новых таблицах включён RLS. `anon` не получает доступа, `authenticated` — только явно разрешённый `SELECT`. Прямые клиентские INSERT/UPDATE/DELETE запрещены, включая администраторов. Серверные секреты Supabase не передаются браузеру.

Привилегии `service_role` — доверенная серверная граница, не замена пользовательской авторизации. Будущие API/RPC обязаны проверять пользователя, курс, роль, версии и идемпотентность. RLS защищает клиентские чтения; доступ к MinIO проверяется отдельно перед выдачей короткоживущей подписи.

## Источники и версии

- `media_sources`: метаданные источника, принадлежащего конкретному уроку и курсу. Проверяются 2 часа, 2 GiB, допустимые контейнеры и YouTube ID. Это не заменяет проверку реального файла FFprobe.
- `media_uploads`: приватные bucket/object key, multipart ID, размер части, срок 24 часа и состояние. Подписанные URL здесь не сохраняются. Список реально загруженных частей следует получать у MinIO.
- Изменение содержимого источника автоматически увеличивает его ревизию. Изменение урока/исходника или потеря готовности исходника помечает связанные AI-пакеты устаревшими.
- Источники и пакеты удерживают урок/курс внешними ключами `RESTRICT`: обычное редактирование не удаляет AI-историю каскадно.
- При устаревании текст сохраняется для автора, но больше не выдаётся студенту как актуальный опубликованный материал.

## Задачи и очередь

`ai_jobs` — состояние задания, UUID идемпотентности в пределах пользователя, версии курса/урока/исходника и закреплённый `config_version_id`. Эти поля нельзя изменить после создания. `ai_job_payloads.input` также неизменяем: изменение входа означает новую задачу.

Долгие задачи будут выполняться через очередь в PostgreSQL Supabase. Данные для неё уже разделены:

- `ai_job_leases`: token, generation, worker и срок аренды, закрытые для клиента.
- `ai_job_steps`: уникальный `(job_id, step_key)` и checkpoint для продолжения отдельного фрагмента/языка.
- `ai_attempts`: последовательность переключений, только alias ключа, результат, время, токены и стоимость. `cost_usd = NULL` означает неизвестную стоимость.

Будущий worker должен атомарно забирать доступную задачу с `FOR UPDATE SKIP LOCKED`, обновлять heartbeat и проверять token/generation на каждой записи результата. Переходы состояний, отмена, восстановление истёкшей аренды и блокировка устаревшего worker **ещё не реализованы этой миграцией**. Клиент не может ставить задачи прямой записью в таблицу.

Секреты провайдеров остаются в серверном `.env`. Конфигурация содержит только имена вида `GEMINI_API_KEY_1`, `OPENAI_API_KEY_1`, `XAI_API_KEY_1`, `HF_TOKEN_1`, `LITELLM_API_KEY_1`. БД отбрасывает известные поля секретов и некоторые явные значения, но это дополнительная защита: перед записью API обязан валидировать типизированную конфигурацию и не принимать произвольные JSON-поля или заголовки. Полная проверка конфигурации относится к этапу 3.

## Публикация

`lesson_ai_bundles` — совокупная версия пакета; `lesson_localizations` и `subtitle_tracks` привязаны к ней и языку, а не создают новые уроки. Изменение текста/субтитров увеличивает ревизию пакета для будущей CAS-проверки редактора.

БД разрешает публикацию только при текущих версиях источников, авторской/административной проверке, наличии трёх непустых лекций и трёх дорожек для видео. Опубликованные тексты и субтитры неизменяемы: правки создаются в новой черновой версии. Одновременно опубликован один пакет урока. Возврат опубликованного пакета в черновик запрещён.

Эта проверка не доказывает качество перевода, корректность таймкодов или полноту лекции. Структурная валидация результата, редактор, контрольные фрагменты и явное подтверждение автора остаются обязательными для этапа 5.

## Поиск и чат

Профиль `course_index_versions` закрепляет провайдера, модель и размерность. Менять профиль существующего индекса нельзя. `course_chunks` проверяет размерность вектора, принадлежность курсу и актуальность источника; материалы тестов/заданий и неопубликованные AI-пакеты в индекс не допускаются. Вектор хранится без фиксированной SQL-размерности, чтобы новая модель могла получить отдельный индекс; начальная размерность — 768.

Сырые чанки доступны только автору/администратору. Для студента позже появится RPC поиска с проверкой опубликованности, текущей ревизии, активного индекса и доступа к курсу. До его реализации прямого поиска для студента нет.

История `chat_threads`/`chat_messages` приватна даже от преподавателя и администратора. Уход с курса, снятие курса с публикации и активная оцениваемая попытка блокируют чтение чата. Генерацию нового ответа и выдачу результата API должен проверять по тем же правилам, включая повторную проверку после долгого вызова модели.

## Награды

`xp_ledger` — журнал первичных наград и отдельных поправок. Уникальность `(user_id, event_type, entity_id)` исключает повторную награду, в том числе при повторном прохождении и смене языка. Значения первичных наград зафиксированы: 10/25/40/100 XP. Серверу не выданы UPDATE/DELETE журнала; отрицательная административная поправка хранится отдельной строкой с причиной.

Есть таблицы настроек, участия, недельных целей, достижений и недельных очков. Цель содержит уникальные дни своей недели; автор и администратор не могут вступить в рейтинг курса. Сырые таблицы рейтинга не являются публичной таблицей лидеров.

Атомарные триггеры начисления, исторический пересчёт, границы недели `Asia/Qyzylorda`, отложенная смена цели, равные места, выход из рейтинга и публичный RPC с псевдонимами реализуются на этапе 7. Само наличие таблиц пока **не начисляет XP**.

## Проверки и источники

`supabase/tests/ai_foundation_test.sql` проверяет ограничения и доступ под реальными ролями PostgreSQL, а также удаление личных диалогов/наград при удалении аккаунта. Все фикстуры находятся внутри транзакции с откатом.

Технические решения учитывают [явные права Data API](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically), [pgvector](https://supabase.com/docs/guides/database/extensions/pgvector) и [закрытый доступ к очередям](https://supabase.com/docs/guides/queues/quickstart). Наличие зелёных SQL-тестов не подтверждает готовность MinIO, worker или внешних AI-провайдеров.
