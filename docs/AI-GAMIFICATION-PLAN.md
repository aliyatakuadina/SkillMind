# SkillMind: AI-функции, трёхъязычные учебные материалы и геймификация

Согласованный план от 20 сентября 2026 года. Статус реализации ведётся в конце документа. Этот план расширяет MVP, описанный в `outputs/SkillMind-LMS-project-plan.md`.

## 1. Результат и принятые решения

AI помогает преподавателю создавать курсы, лекции, конспекты и тесты, а студенту — разбираться в опубликованных материалах. Геймификация показывает личные достижения и добавляет добровольный недельный рейтинг по проверенным учебным результатам.

Основной сценарий: **загрузить видео или вставить YouTube-ссылку → получить субтитры и текстовую лекцию на русском, казахском и английском → отредактировать → подтвердить публикацию**.

- Видео — до **2 часов и 2 ГБ**.
- Исходники и производные файлы — в **MinIO на собственном Docker-сервере**.
- Управление сервером и доступ к собственным модельным API — через **Tailscale** (выбранный вариант из WireGuard/Tailscale).
- Провайдеры: **Gemini, OpenAI, Grok/xAI, Hugging Face и собственные модели через LiteLLM API**.
- Настройки — в административной панели и конфигурационном файле; значения ключей — только в серверном `.env`.
- Денежные и пользовательские квоты приложения отключены. Использование и расходы отображаются информационно; реальные ограничения провайдеров обрабатываются очередью и переключением моделей.
- AI доступен всем зарегистрированным пользователям в рамках существующих ролей и доступа к курсам. Закрытый пилот и прежний бюджет $5 отменены пользователем.
- Материалы публикуются после проверки автора. Новый курс по-прежнему проходит административную модерацию.
- Три языка относятся к учебному контенту, субтитрам и ответам помощника. Интерфейс платформы в этом цикле остаётся русскоязычным.
- Озвучка, дубляж видео, PDF/DOCX-экспорт лекций, игровая валюта и магазин наград в этот цикл не входят.

## 2. Техническая основа и управление AI

### 2.1. Размещение сервисов

Сохраняем React/Vite на Vercel и Supabase для авторизации, PostgreSQL, RLS и очереди задач.

На собственном сервере разворачиваем Docker Compose:

- **API-сервис Python/FastAPI** — авторизованные операции загрузки, временные ссылки MinIO и служебные проверки.
- **Worker** — очередь, FFmpeg, распознавание речи, генерация и перевод.
- **MinIO** — приватное хранение видео, субтитров и результатов.
- **Caddy** — публичный HTTPS для API загрузки и S3-доступа по подписанным ссылкам.
- **Tailscale** — закрытый доступ к управлению сервером и собственным модельным API.

Worker самостоятельно забирает задачи из Supabase. Edge Functions не требуется прямое подключение к частной сети. Обработка продолжается после закрытия браузера. Edge Functions авторизуют пользователя и ставят задачи; долгие операции выполняет Docker из-за [ограничений Edge Functions](https://supabase.com/docs/guides/functions/limits).

MinIO Console, административные порты и собственные модели доступны только через частную сеть. S3-бакеты приватные; публичные HTTPS-адреса обслуживают только авторизованные запросы или временные подписи.

### 2.2. Подготовка существующей модели данных

- Сохранять ID существующих модулей, уроков, элементов и вопросов вместо пересоздания дерева при каждом сохранении.
- Добавить версии содержимого и проверку конфликтов сохранения.
- Обновлять только изменённые сущности; отдельно проверять удаление отсутствующих элементов.
- Не удалять попытки, прогресс и AI-результаты при обычном редактировании.
- Три перевода — версии **одного урока** с общими зачислением, прогрессом, попытками и наградами.
- Для AI-пакета хранить черновую и опубликованную версии. Генерация не заменяет действующий материал без подтверждения автора.
- При изменении исходника помечать результат устаревшим и запрещать автоматическое применение.

### 2.3. Каталог моделей и подключения

Для подключения хранить провайдера, базовый URL, имена переменных ключей, порядок ключей, группу общей квоты и доступные модели. Для модели — поддерживаемые задачи, ограничения контекста, доступность и результат последней проверки.

Обновлять каталог вручную из админ-панели и автоматически раз в сутки:

- Gemini — `models.list`, все страницы.
- OpenAI, xAI и совместимые LiteLLM-сервисы — endpoint списка моделей.
- Hugging Face — каталог моделей, доступных через Inference Providers; наличие на Hub не равно доступности API.
- Endpoint без каталога — явный model ID в конфигурации.

Каталог Gemini для наших задач по официальной документации на 20.09.2026:

| Назначение | Модели |
|---|---|
| Основная генерация | `gemini-3.8-flash`, `gemini-3.7-flash`, `gemini-3.6-flash`, `gemini-3.5-flash` |
| Экономичные | `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` |
| Другие модели каталога | `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.5-pro` |

Источники: [каталог Gemini](https://ai.google.dev/gemini-api/docs/models), [API моделей](https://ai.google.dev/api/models).

### 2.4. Переключение моделей и ключей

Раздельные профили: `video`, `transcription`, `lecture`, `translation`, `quiz`, `chat`, `embedding`.

Порядок внутри провайдера:

```text
Ключ 1: модель A → модель B → модель C
Ключ 2: модель A → модель B → модель C
Следующий провайдер: его ключи и совместимые модели
```

Начальный приоритет текстовых провайдеров: **Gemini → собственный LiteLLM → OpenAI → xAI → Hugging Face**. Порядок редактируется. Подключения без ключей или настроенных моделей пропускаются.

- `429`: учитывать `Retry-After` и сведения о квоте; временно исключать соответствующего кандидата и переходить дальше.
- Ключи одного Gemini-проекта объединять общей квотой: смена ключа не восстанавливает исчерпанный лимит проекта. [Лимиты Gemini](https://ai.google.dev/gemini-api/docs/rate-limits).
- Ошибка ключа отключает подключение до исправления; недоступная модель исключается для соответствующего ключа.
- Временный сетевой сбой — один повтор, затем переключение.
- Ошибка пользовательского ввода и отказ по содержанию возвращаются пользователю без обхода через других провайдеров.
- Все кандидаты недоступны — `waiting_provider`, возобновление после восстановления; пользователь может отменить задачу.
- Готовые этапы сохраняются, смена модели не перезапускает весь процесс.
- Один слой приложения управляет переключением; вложенные повторы SDK отключены.
- LiteLLM обслуживает совместимые вызовы; видео, YouTube и специальные аудиовозможности Gemini — нативный адаптер.
- Кандидаты фильтруются по возможностям задачи. Для embeddings можно менять ключ при той же модели; смена модели требует нового индекса.

Источник: [LiteLLM fallbacks](https://docs.litellm.ai/docs/proxy/reliability).

### 2.5. Административная панель и конфигурация

- **Подключения:** провайдеры, URL, переменные ключей, порядок и состояние.
- **Модели:** обновление каталога, проверка доступности, задачи.
- **Маршрутизация:** цепочки моделей, ключей и провайдеров каждого профиля.
- **Задачи:** этапы, ошибки, повтор, отмена, история переключений.
- **Использование:** токены, минуты, задержки, известная стоимость; неизвестная стоимость не считается нулевой.
- **Материалы:** версии, проверки и индексация.

Секреты: `GEMINI_API_KEY_1`, `GEMINI_API_KEY_2`, `OPENAI_API_KEY_1`, `XAI_API_KEY_1`, `HF_TOKEN_1`, `LITELLM_API_KEY_1` и дополнительные ключи по той же схеме. Панель показывает имена и состояния, не значения. Обновление значения — через серверный `.env` и перезапуск соответствующего сервиса.

`config/ai.yaml` содержит базовые настройки без секретов. Панель создаёт версионированные переопределения в БД с приоритетом над файлом. Нужны просмотр итоговой конфигурации, экспорт без секретов, сброс переопределений и откат. Задача закрепляется за начальной версией конфигурации.

## 3. AI-функции и учебный контент

### 3.1. Видео → три версии материала

Сохраняемые этапы:

1. **Получение:** возобновляемая прямая загрузка файла частями в MinIO либо YouTube ID, ссылка и метаданные.
2. **Проверка:** права, формат, фактический размер, длительность, наличие аудио.
3. **Извлечение:** FFmpeg подготавливает аудиофрагменты; ASR возвращает текст и таймкоды; видеоанализ добавляет сведения со слайдов и экрана.
4. **Нормализация:** устранение дублей границ, общая шкала времени, отметки неуверенно распознанных мест.
5. **Субтитры:** `ru`, `kk`, `en`, WebVTT и SRT.
6. **Лекция:** структурированный материал на основе исходника.
7. **Перевод:** три согласованные версии и общий глоссарий.
8. **Проверка автора:** текст, просмотр субтитров на видео, подтверждение полного пакета.
9. **Публикация и индексация:** студенты и помощник получают подтверждённую версию.

Публичный YouTube передаётся напрямую Gemini. Возможность preview; приватные и unlisted-видео требуют загрузки файла. При недоступности ролика показывать причину и сохранять выполненные этапы. [Поддержка YouTube](https://ai.google.dev/gemini-api/docs/video-understanding).

Для файлов начальный ASR-профиль: Gemini Transcribe → OpenAI Whisper → настроенные совместимые ASR Hugging Face/LiteLLM. Gemini Transcribe документирует казахский язык и таймкоды. [Распознавание Gemini](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe).

- Аудиофрагменты до 10 минут с небольшим перекрытием и восстановлением общей шкалы.
- Перевод сохраняет ID и таймкоды реплик; разбиение длинных реплик выполняется отдельно.
- Повторяется только ошибочный фрагмент или язык.
- Точность таймкодов YouTube проверяется отдельно, проблемные участки отмечаются в редакторе.
- Частичный пакет сохраняется, но не публикуется.
- Временные файлы очищаются после завершения; незавершённые загрузки — через 24 часа; исходник — только при удалении автором.

### 3.2. Лекция и редактор

Каждая версия содержит название, цели, разделы объяснений с привязкой ко времени, определения, глоссарий, примеры, краткий конспект и вопросы самопроверки. Добавленные моделью примеры отделены от содержания источника.

Казахский — на кириллице. Переводы терминов закреплены в редактируемом глоссарии курса.

Редактор показывает видео, реплику субтитров и лекцию. Автор меняет текст/таймкоды и перегенерирует отдельный раздел или язык. Ручные правки не перезаписываются без явного применения результата.

Файловое видео использует `<track>`. YouTube использует встроенный плеер и собственную синхронизированную область субтитров: наши дорожки не загружаются в чужой YouTube-плеер.

### 3.3. Помощник автора

- Структура курса: тема, аудитория, цели, длительность → редактируемые модули и уроки.
- Конспект: материал урока → краткое изложение.
- Тест: выбранные материалы → три поддерживаемых типа вопросов, по умолчанию пять вопросов.
- Объяснения ответов сохраняются в авторском черновике.
- Автор выбирает предложения для применения. Проходной балл, лимит попыток и условия сертификата автоматически не меняются.
- Ключи ответов сохраняются только в защищённых сущностях тестов и исключаются из студенческого поискового индекса.

### 3.4. Помощник студента

- Чат в уроке отвечает на русском, казахском или английском.
- Использует только опубликованные материалы доступного курса.
- Ссылается на уроки, разделы и таймкоды; сообщает о недостатке источников.
- История приватна для пользователя.
- Во время активной оцениваемой попытки чат этого курса недоступен; заброшенную попытку можно завершить предусмотренным действием.
- AI не выставляет оценки, не завершает уроки и не выдаёт сертификаты.
- Поиск: pgvector, начальный профиль `gemini-embedding-001`, размерность 768. Индекс закреплён за моделью и версией материала; новый профиль индексируется отдельно и включается после проверки.

Источник: [Gemini embeddings](https://ai.google.dev/gemini-api/docs/embeddings).

| Группа | Назначение |

| `lesson_ai_bundles`, `lesson_localizations`, `subtitle_tracks` | Черновые и опубликованные версии RU/KK/EN |

Операции: начать/продолжить/завершить/отменить загрузку; создать задачу с source ID и ключом идемпотентности; получить статус/повторить этап/отменить; сохранить правки/подтвердить пакет с проверкой версии; сообщение и ответ с источниками; администратору — обновить модели/активировать конфигурацию.

Статусы: `queued`, `running`, `waiting_provider`, `needs_review`, `completed`, `failed`, `cancelled`. Публикация независима от технического завершения.

## 4. Геймификация

### 4.1. Опыт, уровни, достижения

| Событие | Личный опыт | Недельный рейтинг курса |
|---|---:|---:|
| Первое завершение урока | +10 XP | — |
| Первый успешно пройденный тест | +25 XP | +25 |
| Первое проверенное задание с оценкой от 70 | +40 XP | +40 |
| Первый сертификат курса | +100 XP | — |

Порог 70 — правило награды, не изменение условий сертификата.

- Уровень: `1 + floor(XP / 200)`.
- Одна награда на сущность, независимо от повторов и языка.
- Повторная отметка завершения не даёт XP.
- Посещение сайта, сообщения AI и время открытой вкладки не дают очков.
- Достижения: первый урок, первый тест, десять уроков, первый сертификат, три выполненные недельные цели.
- Цель по умолчанию: действия в три разных дня недели. Выбор от одного до семи дней действует со следующей недели.
- Пропуск недели не отнимает XP и достижения.

### 4.2. Недельный рейтинг

- Добровольный, отдельно для курса; публичный псевдоним без email.
- Только первые успешные тесты и принятые задания после вступления.
- Преподаватель и администратор курса не участвуют в его рейтинге.
- Понедельник–воскресенье, `Asia/Qyzylorda`.
- Равные очки означают равное место.
- Показывать лидеров и положение пользователя.
- Итоги недели фиксируются перед новым периодом.
- Выход скрывает участника, сохраняя личные достижения.

### 4.3. Серверное начисление

Журнал `xp_ledger`, достижения, настройки участия и недельные результаты. Источник — подтверждённые сервером изменения прогресса, тестов, проверки задания и выдачи сертификата. Клиентские `learning_events` остаются аналитикой.

Уникальный ключ награды: пользователь + событие + сущность. Учебное изменение и награда атомарны. Исторические достижения однократно попадают в личный XP, но не в текущий рейтинг/недельные цели. Администратор исправляет награды отдельной записью журнала.

## 5. Реализация, проверка и выпуск

| Этап | Работы | Критерий завершения |
|---|---|---|
| 1. Основа данных | Стабильные ID, версии, сохранение дерева, схемы AI/наград | Редактирование не теряет прогресс и связанные результаты |
| 2. Сервер и медиа | Docker, MinIO, HTTPS, Tailscale, загрузки, очередь | Загрузка 2 ГБ продолжается после обрыва |
| 3. Управление AI | Провайдеры, каталог, .env, конфигурация, панель, fallback | Проверена последовательность моделей и ключей |
| 4. Помощник автора | Структура, конспект, тесты, просмотр, применение | Безопасное применение черновика |
| 5. Трёхъязычное видео | Файл/YouTube, ASR, перевод, лекции, редактор | Проверяемый пакет RU/KK/EN из одного источника |
| 6. Помощник студента | Индексация, чат, источники, языки, доступ | Ответы опираются на доступный опубликованный материал |
| 7. Геймификация | XP, уровни, достижения, цели, рейтинг | Повторы и поддельные события не создают наград |
| 8. Выпуск | Интеграции, мониторинг, резервирование, откат | Основные сценарии проверены в тестовом и рабочем окружениях |

Обязательные проверки:

- Доступ: чужие курсы, исходники, черновики, диалоги, ключи ответов; MinIO отдельно от RLS.
- Переключение: несколько моделей/ключей, общая квота, 429, неверный ключ, модель, тайм-аут, восстановление.
- Очередь: повтор доставки, перезапуск worker, отмена, смена конфигурации, частичные переводы без дублирования результата.
- Видео: MP4/WebM/MOV, отсутствие звука, повреждение, двухчасовая запись, обрыв загрузки, публичный/недоступный YouTube.
- Языки: RU/EN/KK и смешанная речь; имена, числа, термины, полнота, читаемость, синхронизация.
- Качество: минимум десять контрольных фрагментов на каждом языке, оценка преподавателем. Существенные ошибки блокируют публикацию пакета до исправления.
- Чат: ссылки, отсутствие источников, устаревшая версия, отзыв доступа, извлечение ответов теста, инструкции внутри материала.
- Геймификация: конкуренция запросов, повторы, языки, повторная проверка задания, границы недели, выход, исторический пересчёт.
- Регрессия: pgTAP, Playwright, lint/build, мобильный интерфейс, клавиатура. Тесты Python-сервисов добавить в CI.

Выпускать по этапам с отдельными переключателями. После проверки открывать соответствующим ролям без пользовательских квот. Наблюдать за очередью, worker, диском, ошибками моделей и качеством переводов.

Откат отключает функцию или возвращает конфигурацию, сохраняя материалы, прогресс и награды. Резервная копия MinIO — вне основного диска; обязательна проверка восстановления.
